# Повторный проход: T0001–T0050

## Правило приёмки

Пользователь потребовал начать заново и выполнять все пункты. Это активная первая
порция нового прохода, а не 50 автоматически закрытых задач. Исходные ID и старые
доказательства сохранены. Следующую порцию не начинать, пока эта не завершена.

## Воспроизведённые и исправленные разрывы

- `summarize([])` выдавал PASS; теперь BLOCKED, 0%.
- Явный FAILED/CANCELED/неизвестный статус с ok=true давал legacy PASS и полный балл; теперь PARTIAL и ноль.
- required=false мог ослабить явно объявленную обязательную стадию; теперь контракт вызывающего приоритетен.
- Повтор имени, malformed status/required/name и противоречивые поля не дают успех.
- God/async считали PASS_BLOCKED и BLOCKED_SIMULATION завершённым результатом; теперь используют общий outcome.
- CLI AI/God/async возвращали 0 при неполном или отсутствующем результате; теперь nonzero, включая dry-run, который не доказывает полный результат.
- AI RunReport публикует общий outcome с required-флагами; failed payload не становится success.
- Стандартный finalizer проверяет полный STAGE_RECORDS, а не только фактически вернувшиеся стадии.
- Неверный формат аппаратного inventory теперь даёт отказ preflight, а не исключение.
- summarize разгружен ниже лимита 60 строк; старое исключение удалено из бюджета.
