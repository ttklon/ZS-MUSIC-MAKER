# Рабочая порция T0011–T0040

Статус проверки Windows добавляется после выполнения workflow. Это не релиз.

## T0011–T0020 — обязательства по результату

- **T0011 контракт:** docs/RESULT_CONTRACT.md, четыре разных вида содержимого и
  unverified_audio. Скачанный файл, TTS и RVC не доказывают автоматически спетую песню.
- **T0012 baseline:** до изменений narration.verdict давал HIT по master_path и
  отсутствию lyrics/voice блокировок; тест test_verdict_hit_requires_master_lyrics_and_voice
  принимал даже несуществующий файл. Это воспроизведено и заменено отрицательной регрессией.
- **T0013 решение:** разделены физический артефакт, происхождение producer, тип
  запроса и качество. Альтернатива «считать vocal.ok пением» отклонена.
- **T0014 реализация:** app/pipeline/artifact.py и result.py проверяют реальный WAV,
  потоковую декодируемость, длительность/каналы/амплитуду, хэш и структуру происхождения.
- **T0015 интеграция:** agent_task JSON включает result, CLI отдаёт nonzero при
  непринятом результате. Narration не пишет «Трек готов» только по пути. Creation
  проверяет новый контракт, а не HIT, и показывает причины.
- **T0016 отказы:** отсутствующий/битый/тихий/NaN/Inf/вне диапазона WAV, чужой hash,
  TTS вместо singing, незавершённые стадии и отмена не становятся готовой песней.
- **T0017 регрессия:** test_result_acceptance_contract.py, test_agent_guide.py,
  CLI/UI тесты. PCM-фикстуры реальны как файлы, но не являются нейромузыкой.
- **T0018 Windows:** result-outcome-hardware-contracts проверяет настоящие PCM
  файлы на Windows; packaged-product-specification проверяет запуск окна.
- **T0019 приёмка:** запрещён ложный HIT по source=rvc/high_score/пути. Producer
  manifest привязывается к аудио; quality_accepted остаётся false.
- **T0020 сопровождение:** docs/RESULT_CONTRACT.md описывает доверенную природу
  manifest и оставшуюся интеграцию реальных backend. Нет фиктивного checks=true
  в production, существующие producer пока дают degraded без manifest.

Пакет принимает **контракт и его применение**, не качество или создание песни.
Генерация singing и прохождение lyrics/voice в renderer остаются другими пакетами.

## T0021–T0030 — измеренные аппаратные профили

- **T0021 контракт:** измерения CPU/RAM/диска отдельно от inference и поддержки GPU;
  unknown представлен null/not_measured, все продуктовые профили пока unverified.
- **T0022 baseline:** прежний HARDWARE.md содержит расчётные профили и цены, не
  реальные замеры; detect_budget сообщает объём/число потоков, не прохождение сценария.
- **T0023 решение:** отдельный read-only отчёт без автоматического выбора backend
  по произвольным порогам; бюджет передаётся явно для конкретного движка.
- **T0024 реализация:** app/ai/profiles.py, preflight_resources и инструмент
  tools/measure_hardware_profile.py. Без бюджета/ресурса, с NaN/Inf или нехваткой — отказ.
- **T0025 интеграция:** inventory включён в CLI health; отдельный инструмент
  сохраняет JSON без загрузок и изменения настроек. Старые эвристики моделей не
  объявлены заменёнными новым API.
- **T0026 отказы:** недоступный диск и ошибки RAM отражаются в errors; неизвестное
  GPU не превращается в подтверждённый CPU fallback. Никаких автоустановок.
- **T0027 регрессия:** test_hardware_profiles_contract.py: настоящие RAM/диск,
  неизвестный путь, неверные бюджеты и запрет принятия профиля без inference.
- **T0028 Windows:** read-only измерение настоящего GitHub Windows runner с JSON
  artifact и annotation. Это inventory, не benchmark модели и не домашний ПК.
- **T0029 BLOCKED:** нет принятого реального сценария моделей на матрице CPU/CUDA/AMD,
  нет доказанных минимальных требований и времени/RAM/VRAM полного рендера.
- **T0030 BLOCKED:** пакет нельзя закрыть до T0029. Рекомендации HARDWARE.md
  помечены как исторические оценки, а не утверждённые конфигурации.

## T0031–T0040 — модель результата стадии

- **T0031 контракт:** success/degraded/blocked/failed/canceled с required-флагом,
  отсутствующие required_names явно становятся blocked. Пустой прогон не успешен.
- **T0032 baseline:** StageResult.ok для BLOCKED остаётся true как legacy API;
  старый summarize([]) может выдавать PASS, percent считает работу, не готовность.
- **T0033 решение:** канонический outcome добавлен рядом с legacy verdict/percent;
  немедленное удаление старых полей отклонено до миграции потребителей.
- **T0034 реализация:** app/pipeline/outcome.py, CANCELED в StageStatus, required в
  сериализации; явный статус важнее legacy ok. Причина отказа не исчезает.
- **T0035 интеграция:** summarize и finalize_report включают outcome; QA failure
  и dry/partial рендер не дают общего успеха. Классический --run использует
  outcome при его наличии, agent-hit использует типизированный content result.
- **T0036 отказы:** required blocker, unknown status, отмена, placeholder,
  пропущенная стадия и QA error проверяются; необязательная ошибка даёт degraded.
- **T0037 регрессия:** test_task_outcome_contract.py и совместимые старые stage
  tests; CLI regression отвергает legacy PASS при новом blocked outcome.
- **T0038 Windows:** canonical outcome tests на Windows, без двойника ОС; проверка
  контракта не является реальной отменой дерева процессов (это отдельный пакет 15).
- **T0039 BLOCKED:** не все legacy AI/God/async потребители переведены на канонический
  outcome и не везде перечислен полный обязательный набор стадий.
- **T0040 BLOCKED:** общая приёмка единой модели для всех публичных входов невозможна
  до T0039. Старые verdict/ok/percent пока нельзя считать продуктовой готовностью.
