## T0141–T0150 — отмена дерева процессов

- T0141: контракт различает запрос stop, stopping, root.close, результат команды
  tree termination, canceled и timedOut; сохранность данных и границы описаны.
- T0142: baseline child.kill(SIGTERM/SIGKILL) воздействовал только на корневой PID;
  prepareWorkspace не имел отмены. Воспроизведение — Python с живым grandchild.
- T0143: POSIX отдельная process group и Windows taskkill /T /F без shell;
  подготовка через AbortController, не небезопасное прерывание JS/fs потока.
- T0144: process-control.js и tasks ожидают close + termination; canceled=true
  запрещает ok, даже если процесс успел вернуть 0. Повторная stop идемпотентна.
- T0145: task-runner держит общий slot на время подготовки/отмены; abort проверяется
  в копировании и перед spawn. После abort Python не запускается.
- T0146: неуспешное подтверждение cleanup не освобождает slot; пользователь получает
  явную причину. При отмене частичного copy данные/модели не удаляются, retry возможен.
- T0147: настоящий Python→grandchild держит файл, тестирует cancel и timeout,
  проверяет отсутствие исполняющегося PID и следующий subprocess с тем же file lock.
  Отдельный deferred prepare test проверяет abort/no-spawn/slot release.
- T0148: этот реальный child/byte-lock сценарий проходит на Windows; тест не
  заменяет команду taskkill двойником и не требует действий на ПК пользователя.
- T0149 BLOCKED: нет полной проверки настоящих pip/model worker деревьев, detached
  потомков, гонки исчезновения родителя и восстановления окружения после force-stop.
- T0150 BLOCKED: до T0149 нет универсальной гарантии cleanup. confirmed означает
  успешную команду и root close, не Job Object или независимую перепись всего дерева.

## T0151–T0160 — таймауты и отсутствие активности

- T0151: отдельно total hard deadline, heartbeat, silence warning и stage watchdog;
  liveness не выдаётся за измеренный прогресс/качество/процент.
- T0152: baseline был только общий setTimeout→kill корня; долгий CPU не имел
  наблюдаемой активности, Windows stage watchdog отмечал timeout после возврата.
- T0153: сохранены task-specific hard limits; тишина только предупреждает,
  не auto-kill. Parent monitor отделён от model execution/stage measurements.
- T0154: monitorActivity elapsed/silence каждые 5s, quiet после 60s; hard deadline
  использует остановку дерева. stage_activity каждые 15s явно сообщает liveness.
- T0155: creation показывает heartbeat/stopping/cleanup-failed в своей сессии;
  sequential_runner оборачивает stage invoke в stage_activity вместе с watchdog.
- T0156: monitor очищается на error/close, heartbeat thread в finally; CPU тишина
  не прерывает функцию. Недоказанный native-stage timeout не становится success.
- T0157: тесты удерживают silence без early kill, проверяют остановку timer/thread,
  настоящий total timeout дерева и фиксацию timedOut отдельно от canceled.
- T0158: Windows исполняет monitor и реальные subprocess deadlines; stage heartbeat
  проверяется CPU fixture без модели. Это не измерение производительности inference.
- T0159 BLOCKED: Windows stage watchdog не умеет безопасно прервать native/Python
  stage до возврата. Требуется process isolation и реальные модели/долгие замеры.
- T0160 BLOCKED: до T0159 полный пакет stage limits не принят.
