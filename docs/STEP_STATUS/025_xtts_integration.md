# PLAN_v39 — ШАГ 025: интеграция XTTS-v2

## Реализованный контракт

`stage_vocal` больше не вызывает метод TTS неявно внутри большой стадии. Вызов вынесен в `render_xtts_vocal()`, который формирует контракт `text`, `file_path`, `language="ru"` и только при существовании файла пользователя передаёт `speaker_wav`. Успешным результатом считается только реально созданный файл размером более 100 байт.

| Сценарий | Поведение |
|---|---|
| Совместимый XTTS handle создаёт WAV | Возвращается `ok=True`, `vocal_path` и `engine=xtts_v2`. |
| Handle завершился без файла или создал пустой файл | Возвращается `ok=False` с `XTTS did not produce an audio file`. |
| Handle выбросил исключение | Возвращается `ok=False` с контекстом `XTTS synthesis failed`. |
| Модель недоступна | Существующая optional-стадия возвращает `skipped: no tts model`; подмена вокала не создаётся. |

## Доказательства

Fake XTTS handle подтвердил фактическую передачу `speaker_wav` и `language`, создание WAV и корректный success-path. Отдельная заглушка с пустым файлом подтвердила отсутствие ложного успеха. На момент приёмки: `pytest tests/` — **67 passed**, `compileall` — успешно, AST-аудит — **0**.

> Coqui TTS / XTTS-v2 не установлены в sandbox. Следовательно, интеграционный контракт проверен, но реальный голосовой рендер не заявляется как выполненный. ШАГ 026 отдельно проверит метрики и честную fallback-цепочку.
