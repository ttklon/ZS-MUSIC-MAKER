# PLAN_v39 — ШАГ 029: интеграция Demucs htdemucs

## Реализованное поведение

Роль `stem_splitter` уже была зарегистрирована как `demucs` с бюджетом 6 GB VRAM и имеет отдельный маршрут `tools/pull_ai_models.py`, вызывающий `demucs.pretrained.get_model("htdemucs")`. В обработке track dossier устранена опасная привязка к индексу `sources[0, 3]`.

| Сценарий | Поведение |
|---|---|
| Demucs handle доступен | Индекс `vocals` определяется по `model.sources`, затем сохраняется `vocals_path`. |
| Порядок stem-источников иной | Используется фактический индекс `vocals`, а не жёстко зашитый номер. |
| В модели нет источника `vocals` | Возвращается диагностируемая ошибка; неверный stem не выдаётся за вокал. |
| `stem_splitter` недоступен | Optional stage возвращает явный `skipped: stem_splitter unavailable`. |
| Целевой каталог не существует | Создаётся перед записью WAV. |

## Доказательства

Тесты подтверждают выбор `vocals` по произвольному declared порядку и явный отказ для модели без такого источника. На момент приёмки: `pytest tests/` — **75 passed**, `compileall` — успешно, AST-аудит — **0**.

> Demucs и его веса отсутствуют в sandbox. Поэтому реальный demixing не заявляется как выполненный; проверены registry/pull integration, runtime contract и безопасная обработка результата.
