# PLAN_v39 — ШАГ 030: метрики, fallback и валидация Demucs htdemucs

## Quality contract

После записи вокального stem вызывается `validate_stem_artifact(original, stem)`. Output должен пройти базовый audio gate и иметь длительность в диапазоне 95–105% длительности входного трека. Такой более узкий диапазон обоснован тем, что Demucs разделяет источники, а не создаёт новую аранжировку.

| Проверка | Реакция |
|---|---|
| Input пригоден для чтения | Иначе `stem input audio is unreadable`. |
| Stem читаем, не silent, без клиппинга | Иначе причина базового audio gate. |
| Длительность stem — 95–105% input | Иначе `stem duration diverges from input`. |
| Demucs unavailable | Explicit `skipped`, ASR использует исходный audio только по уже существующему fallback-правилу. |

## Доказательства

Регрессия создаёт 1-секундный original, корректный 1-секундный stem и 0.875-секундный усечённый stem. Корректный файл проходит, усечённый отклоняется до его использования следующей стадией. На момент приёмки: `pytest tests/` — **76 passed**, `compileall` — успешно, AST-аудит — **0**.

> Реальная Demucs-модель в sandbox недоступна. Проверка доказывает acceptance contract записанного stem, но не служит утверждением, что реальный demixing уже выполнен на данном окружении.
