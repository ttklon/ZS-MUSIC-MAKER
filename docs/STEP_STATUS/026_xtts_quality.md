# PLAN_v39 — ШАГ 026: метрики, fallback и валидация XTTS-v2

## Quality contract

`validate_vocal_artifact()` применяет общий audio gate и добавляет связь между длиной текста и минимальной длительностью результата. Количество токенов определяется детерминированно, а минимальная ожидаемая длительность ограничена диапазоном 0.25–3.0 секунды. Поэтому silent, нечитаемый или несоразмерно короткий WAV не может быть признан готовым вокалом.

| Сценарий | Поведение |
|---|---|
| XTTS создаёт подходящий WAV | `ok=True`, возвращаются `quality` и метрики audio/text. |
| XTTS выдаёт пустой, silent или слишком короткий файл | Primary result не проходит quality gate. |
| XTTS недоступен или output отклонён | Запускается `voice_synth.synth(engine="auto")`. |
| Fallback не создаёт файл | Возвращается `ok=False` и `no fallback TTS engine produced audio`. |
| Fallback создаёт непригодный файл | Возвращается `ok=False` с причиной quality gate; не маскируется как XTTS. |

## Доказательства приёмки

Тесты подтверждают: валидный WAV проходит, короткий относительно текста WAV отклоняется, fallback копирует и валидирует реальный WAV, отсутствие любого движка даёт честный failure. На момент приёмки: `pytest tests/` — **70 passed**, `compileall` — успешно, AST-аудит — **0**.

> Coqui XTTS-v2 по-прежнему отсутствует в sandbox. Реальная генерация голосом не заявляется как выполненная; реализованы и проверены только интеграционный и safety-контракты.
