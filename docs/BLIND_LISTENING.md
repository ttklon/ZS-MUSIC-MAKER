# Слепое прослушивание: протокол и чек-лист

Этот документ — инструкция, а не отчёт. Отчёт заполняется **по результатам
прослушивания**, поэтому здесь нет ни одной заранее «зелёной» галочки: пока
человек не прослушал треки, результат считается неизвестным.

## Зачем

Все технические гейты (§7.2 плана) измеряют физику: громкость, пики, crest,
корреляцию, контраст дропа, энтропию повторов. Они **не** отвечают на главный
вопрос — «звучит ли это как работа человека». На него отвечает только слепое
сравнение с настоящими треками.

## Что нужно

1. Пять демо из `tools/generate_demos.py` (`output/demos_run/demos/*_streaming.wav`)
   и пять референсов вашего жанра (обычные коммерческие треки, которые вам
   нравятся).
2. Наушники или мониторы + телефон/колонка (второй проход — на «бытовухе»).
3. Один-два человека, которые не знают, какие треки сделаны программой.

## Как проводить

1. Громкость всех файлов выровнена по −14 LUFS (мастера уже такие), поэтому
   крутить ручку между треками не нужно.
2. Перемешайте 10 файлов в случайном порядке (например, `shuf` или любым
   плеером со случайным порядком). Запишите порядок под номерами 1…10, не
   подписывая, где что.
3. Слушайте по 30–45 секунд с каждого места (начало, середина, дроп).
4. Для каждого трека отметьте по 5 пунктам, 1–5 баллов:
   * «живость» — есть ли микродинамика, дыхание, неровности;
   * «не пластик» — не слышно ли синтетических артефактов, мёртвых хвостов,
     бесконечных одинаковых повторов;
   * низ — читается ли бочка/808, нет ли «каши» и гула;
   * верх — нет ли шипения, цыканья, «стекла»;
   * общее впечатление — включили бы вы это второй раз.
5. После всех 10 треков откройте ключ (какие номера были ваши) и сведите
   таблицу.

## Критерий приёмки

Программа считается «звучащей как человек», если одновременно:

* средний балл демо по «живости» и «не пластик» ≥ 3.5 из 5;
* ни одно демо не проигрывает референсам больше 1 балла по «общему
  впечатлению» в среднем;
* хотя бы один слушатель не смог уверенно отделить демо от референсов
  (то есть «угадывание» ближе к случайному, а не 10 из 10).

Если критерий не выполнен — это не повод «подкрутить отчёт»: в отчёте
прослушивания фиксируется, какие стадии дали провал (например, банк сэмплов,
гармония или плотность аранжировки), после чего работа продолжается.

## Форма отчёта

```
Дата: ____  Слушатели: ____  Тракт: ____ (наушники / мониторы / телефон)

№  файл        живость  не пластик  низ  верх  общее   комментарий
1  ...            4        4         5    4     4       «на дропе не хватило ширины»
...
10 ...

Ключ: 1 = drift_phonk_demo, 2 = reference (исполнитель)…
Средние по демо: живость ___  не пластик ___  общее ___
Средние по референсам: живость ___  не пластик ___  общее ___
Вердикт: ПРОЙДЕНО / НЕ ПРОЙДЕНО (по критерию выше)
```

## Что уже сделано со стороны программы

* Пять демо собираются одной командой: `python tools/generate_demos.py`
  (75 секунд на трек, жанры: drift phonk, trap, house, hard rock,
  dark ambient). Отчёт с гейтами — `output/demos_run/demos/demos_report.json`.
* Все мастера выровнены по −14 LUFS ±0.5 и −1 dBTP, поэтому сравнение честное
  по громкости.
* Каждое демо имеет `humanity` и `repetition` в отчёте бита: дрейф темпа,
  шум комнаты, энтропию типов тактов — то, что раньше выдавало «машинность».

Таблица выше заполняется вручную после прослушивания; в репозитории она
появится как `docs/BLIND_LISTENING_RESULT.md` только с реальными цифрами.
