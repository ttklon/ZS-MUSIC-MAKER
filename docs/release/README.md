# Блокеры и ворота публикации

Это действующий реестр, а не отчёт о готовности. Источник P0/P1 —
[blockers.json](blockers.json); каждый дефект имеет сценарий, воспроизведение,
ожидание/наблюдение, зависимости, regression и ответственного product-maintainer.
Сюда включены известные обязательные разрывы, а не заявление об отсутствии других.
F01: `_generate_hit` передаёт только три поля в `make_one`; это ещё не исправлено.
Реестр пополняется при каждом новом воспроизводимом разрыве.

## Правило приоритета и закрытия

P0 — ломает обязательный результат/права/правдивость успеха; P1 — обязательная
надёжность, безопасность и поддерживаемость. Сначала зависимости, затем P0/P1,
не косметические релизы. `resolved` требует resolution_evidence; исправление
проверяется сценарием regression, Windows протоколом и наблюдаемым результатом.
Тест реестра не закрывает перечисленные дефекты. Rollback — revert изменения,
не удаление проектов/моделей и не перезапись опубликованных файлов.

Baseline: опубликован v42.0.39; development T0011–T0070 имеет ограничения,
перечисленные в реестре. `python tools/release_gate.py` сейчас возвращает 1,
называет открытые блокеры и отсутствующие доказательства G0–G9. Это ожидаемый
отказ публикации, а не падение сборки или запрет инженерных проверок.

## Обязательные ворота

| ID | Требуемый наблюдаемый результат |
|---|---|
| G0 | согласованный scope и все обязательные сценарии |
| G1 | чистая Windows NSIS установка без внешнего Python/Node |
| G2 | загрузки моделей, отказ/повтор/отмена, восстановление и offline |
| G3 | реальный инструментал из поддерживаемого backend |
| G4 | отдельно собственный разрешённый вокал и автоматическое пение |
| G5 | сохранение, повторное открытие, правка и история без потери исходника |
| G6 | метрики аудио, права использованных ресурсов и человеческое прослушивание |
| G7 | десять коротких и три полных прогона; failure matrix и замеры железа |
| G8 | обновление, publisher/signature и согласие на опасные действия |
| G9 | нет открытых обязательных P0/P1 |

`acceptance.json` намеренно пуст по смыслу: accepted=false. Будущая приёмка
привязывается к **полному SHA исходного коммита сборки**, каждому gate нужны
accepted=true, reviewer и непустые evidence. Evidence — относительный путь
внутри checkout, SHA-256 фактических байтов и kind measured/human_review.
Документы с отметкой «принято» без измерений/прослушивания запрещены политикой.
Синтетический позитивный fixture в тестах не является такой приёмкой.
Хэш проверяет целостность, а не честность автора/качество музыки и не является
криптографической подписью рецензента. Нужен независимый review доказательств.

Оба publish-release workflow выполняют gate **перед публикацией**, без
continue-on-error. Новая версия обязательна: существующие releases не очищаются,
overwrite_files=false, проверка списка releases должна успешно прочитаться
(ошибка API не означает «релиза нет»). Публикации сериализованы общим concurrency.
Сборки и CI artifacts допустимы при закрытых воротах; они не меняют latest.
Никакой новый релиз в рамках этой работы не запускается. Старые версии этим
изменением не исправляются. Для реального выпуска нужен отдельный протокол
сборки исходного SHA и безопасной доставки evidence; сейчас его нет.
