# ZS Music Maker — GLOBAL ARCHITECTURAL AUDIT V4 (Singularity)
========================================================================

Четвертый этап аудита ("Сингулярность") выявил системные проблемы, мешающие программе стать полноценным, автономным и профессиональным программным продуктом.

## 1. "Фрагментированная Документация" (Documentation Chaos)
**Проблема:** История проекта разбросана по 15+ файлам `CHANGELOG_vX_APPEND.md`. Пользователю невозможно понять актуальное состояние системы без прочтения всех патчей.
**Решение:** Консолидация всей документации в единый `docs/WIKI.md` и создание авто-генерируемого `CHANGELOG.md`.

## 2. "Отсутствие Единого Инсталлятора" (Deployment Gap)
**Проблема:** Нет единого скрипта установки. Пользователь должен вручную запускать разные `.bat` и `.sh` файлы, что снижает автономность.
**Решение:** Создание универсального `install.py`, который сам определяет ОС, ставит зависимости, проверяет GPU и скачивает базовые модели.

## 3. "Ручная Система Плагинов" (Manual Plugin Discovery)
**Проблема:** Новые плагины в `app/plugins/` нужно прописывать в коде вручную. Нет автоматического обнаружения (discovery) новых эффектов.
**Решение:** Внедрение динамического импорта плагинов из папки `plugins` при запуске.

## 4. "Линейный Рост Логов" (Infinite Log Growth)
**Проблема:** `app/core/logger.py` пишет всё в один файл. При долгой работе (24/7) лог раздуется до гигабайт, забив диск.
**Решение:** Внедрение `RotatingFileHandler` с ограничением по размеру и количеству файлов.

## 5. "Медленные Чекпоинты" (Inefficient Checkpoint I/O)
**Проблема:** Чекпоинты сохраняются в JSON. При работе с большими массивами метаданных или сэмплами это создает задержки.
**Решение:** Переход на бинарную сериализацию (например, `pickle` или `msgpack`) для промежуточных данных аудио-стадий.

## 6. "Отсутствие Самодиагностики Жанров" (Genre Fragility)
**Проблема:** У нас 119 жанров, но нет теста, который проверяет их все разом на валидность конфигов.
**Решение:** Создание `tools/genre_validator.py` для автоматической проверки всех 119 профилей.

## 7. "Жесткая Привязка к Путям" (Hardcoded Path Risks)
**Проблема:** Некоторые модули всё еще используют относительные пути, которые ломаются при запуске из других директорий.
**Решение:** Полный переход на `Path(__file__).resolve()` во всех критических узлах.

## 8. "Слабая Система Помощи CLI" (Poor CLI UX)
**Проблема:** Флаг `--help` выдает скудную информацию. Пользователь не знает, какие 119 жанров доступны.
**Решение:** Расширение CLI через `argparse` с динамическим выводом списка доступных жанров и команд.

## 9. "Отсутствие Защиты от Переполнения Буфера" (Audio Buffer Safety)
**Проблема:** В DSP операциях нет проверок на `NaN` или `Inf` в аудио-массивах, что может привести к "цифровому взрыву" (клиппингу) в цепочке эффектов.
**Решение:** Внедрение санитайзера аудио-данных на входе в каждый плагин.

## 10. "Моноязычность Интерфейса" (Lack of i18n)
**Проблема:** Логи и сообщения перемешаны (русский/английский). Нет структуры для локализации.
**Решение:** Создание базового модуля `i18n` для разделения логики и текстовых ресурсов.
