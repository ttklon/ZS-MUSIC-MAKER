# ZS Music Maker — «Hit Locked Pro»

> **Версия:** `41.0.0-alpha.16` (источник правды — [`version.json`](version.json))
> **Платформа:** Windows 11; локальные модели устанавливаются отдельно
> **Состояние:** идёт рефакторинг v41 — см. [`docs/ROADMAP.md`](docs/ROADMAP.md)

Прототип локальной музыкальной студии: из жанра, темы и референсов собирает
бит, может обработать готовую запись вокала, сделать микс и мастеринг. Не все
тяжёлые движки доступны без установки, качество и коммерческий успех не
гарантированы. Проверка всего сценария на Windows 11 ещё не завершена.

## Быстрый старт (Windows 11)

```bat
scripts\setup.cmd            :: один раз: проверка Python, venv, зависимости, health-check
scripts\run_silent.cmd       :: запуск мастера без окна консоли (как обычное приложение)
scripts\run.cmd              :: то же, но с консолью (видно прогресс и ошибки)
scripts\build_exe.cmd        :: собрать exe (PyInstaller, onedir) в dist\
scripts\verify.cmd           :: полная проверка: тесты, смоуки, аудиты
python main.py --console     :: консольный режим
```

Мастер — пять шагов: **жанр и тема → материал → голос → тонкая настройка → запуск**.
Своя запись голоса — основной путь; RVC включается отдельно и требует своей
модели. В мастере можно выбрать экспериментальный инструментал ACE-Step 1.5
через локальный сервер; настройка и ограничения AMD — в [INSTALL.md](INSTALL.md).
Журналы и крэш-репорты лежат в `%LOCALAPPDATA%\ZS Music Maker\logs`.

Полезные режимы:

```bat
python main.py --version
python main.py --list-genres
python main.py --god                 :: полный пайплайн одной командой
python main.py --dry-run             :: прогон без тяжёлых моделей
python main.py --health              :: проверка зависимостей, не тест inference
python main.py --readiness           :: внутренний технический чек-лист
python main.py --ai-status           :: доступность AI-ролей без загрузки весов
python main.py --score output\master.wav   :: hit-score + разбор по метрикам
python main.py --smoke               :: smoke-набор (God Mode + аудио-качество)
```

## Приложение на Electron

**Скачать установщик под Windows 11:**
[`ZS-Music-Maker-Setup-1.0.0.exe`](https://github.com/ttklon/ZS-MUSIC-MAKER/releases/latest/download/ZS-Music-Maker-Setup-1.0.0.exe)
(или [portable-EXE](https://github.com/ttklon/ZS-MUSIC-MAKER/releases/latest/download/ZS-Music-Maker-1.0.0-portable.exe),
все сборки — в [релизах](https://github.com/ttklon/ZS-MUSIC-MAKER/releases)).
Сборка не подписана: Windows 11 покажет SmartScreen при первом запуске.

Оболочка приложения живёт в `desktop/` и не требует Python для просмотра
данных: версия, 120 жанров с пресетами, матрица модулей, досье и честный
процент готовности читаются из файлов проекта. Бит собирается там же: раздел
«Бит» рендерит трек на JavaScript (`desktop/src/core/audio/` — порт
`modules/beat/`), играет его и сохраняет WAV. Ударные берутся из сэмплового
банка `data/samples/` (32 CC0-one-shot, 6 инструментов) — статус движка
`REAL_PASS`, как в Python; галочка «банк сэмплов» переключает на синтез. Раздел «Запуск» вызывает ту
же команду, что и терминал (`python main.py …`), и показывает вывод
построчно.

```bat
cd desktop
npm install
npm start              :: окно
npm run snapshot       :: обновить снимок чисел (нужен Python)
npm test               :: 371 тест оболочки и аудио-движка, графика не нужна
npm run preview        :: посмотреть окно в браузере
```

Графическое окно в окружении сборки не запускалось (нет Xvfb и GTK): проверены
синтаксис, логика на настоящих файлах, рендер в DOM-двойнике, сверка расчёта
готовности с `python -m tools.readiness` и сверка аудио-движка с Python —
таблицы ритма, АЧХ фильтров против scipy и 20-секундный рендер, который
читается как обычный WAV. Инсталлятор не собирался. Подробности —
`desktop/README.md`.

## Что честно работает

| Слой | Статус |
|---|---|
| CLI, визард, оркестратор | доступен; GUI и Windows требуют проверки на целевом ПК |
| Окно на Electron (`desktop/`) | данные, запуск задач и сборка бита на JS (сэмпловый банк → REAL_PASS) подключены; сам Electron в среде сборки не запускался |
| Анализ/грув/бит (librosa + процедурный синтез) | работает |
| Микс + сайдчейн, мастеринг 8 стендов, true-peak −1 dBTP | работает |
| Запись и обработка своего вокала | обработка файла проверена; запись через микрофон на Windows не проверена |
| Релиз-пакет и текст | создаются; LRC/SRT без синхронизации не создаются, ISRC не выдаётся автоматически |
| TTS-вокал (Silero/XTTS/bark/pyttsx3) | работает при наличии движка, иначе BLOCKED |
| RVC (свой голос модели) | встроенное обучение не подключено, inference без своей модели BLOCKED; Windows не проверен |
| ACE-Step / MusicGen / Demucs / SDXL / CLAP / LLM | реальные модели и Windows не проверены; без весов/сервера недоступны |

## Ограничения сценария

Анализ аудиореференсов оценивает музыкальные признаки, но не составляет
полноценный профиль исполнителя. Для текста можно ввести ручные референсы и
непроверенные заметки о темах. Опциональная галочка на шаге материалов включает
локальное распознавание через faster-whisper: первые 7 файлов, до первых 180 с
каждого. Если введён собственный текст песни, он приоритетен и ASR пропускается;
в сухом прогоне модель тоже не запускается. Результаты, пропуски и ошибки
отмечаются в `creative_context.reference_asr` в `report.json`.

Нужны установленные пакет и локальные веса: установка и явное скачивание описаны
в `INSTALL.md`. Во время обработки веса автоматически не скачиваются. Выбор
CUDA допускается только при доступном CTranslate2 CUDA и подходящей свободной
видеопамяти; AMD/ROCm и DirectML не считаются автоматически CUDA. При переходе
на CPU нужна достаточная свободная RAM; оценка не гарантирует отсутствие OOM.
Реальный Whisper, Windows и пение с музыкой здесь не проверены. Вокал из
референса не отделяется, VAD может пропустить пение, а распознанный текст может
быть неверным или выдуманным: проверяйте его и используйте разрешённые материалы.

Полная расшифровка не сохраняется и не передаётся LLM, однако её частые слова,
счётчики и ваши заметки могут попасть к облачному провайдеру, если он выбран;
ключевые слова также сохраняются в отчёте. Не включайте опцию для приватного
аудио без понимания этих последствий. Автоматический поиск трендов не подключён.
Без доступной LLM используются шаблоны, которые не учитывают этот контекст
и не гарантируют осмысленную проработку темы.
Микс принимает готовую запись голоса: программа не превращает её автоматически
в новое исполнение созданного текста. Если минус выбран как готовый файл, он
подставляется в диалог записи вместе с длительностью проекта (до 300 с). Запись
требует совместимого микрофона; запись под минус также требует работающего
full-duplex ввода/вывода и наушников. Программа проверяет поддерживаемые частоты
устройств, может выбрать другую частоту или свести стереоминус к моно и сообщает
об этом. Автоматической компенсации задержки нет — сдвиг подбирается вручную.
Запись сохраняется в WAV float32 без намеренной потери точности; при пиках около
предела показывается предупреждение. RVC и коррекция высоты по умолчанию
выключены; вокальные эффекты можно отключить отдельно (микшер всё равно
применяет фильтрацию и регулировку уровня). Явно выбранный, но отсутствующий,
тихий или полностью обрезанный сдвигом вокал не подменяется инструменталом.
Если часть вокального сигнала выходит за границы минуса после сдвига, это
отмечается в отчёте и в интерфейсе; исходный дубль не обрезается.

Индекс голосового архива обновляется атомарно под кооперативной блокировкой.
При повреждённом индексе он не затирается: запись сохраняется отдельно, а
пользователю показывается предупреждение. Для восстановления сначала закройте
все экземпляры программы и сделайте резервную копию всей папки `voice_vault/`;
автоматическое восстановление индекса пока не реализовано. Не удаляйте дубль
или файл блокировки во время работы программы. Два существующих индекса Voice Vault
пока не объединены и не мигрируются автоматически. Длительность по индексу и
буквы в записанных фразах не подтверждают фонемный состав или обучение модели;
старые поля профиля об обучении могут быть недостоверными. Минус, выбранный в
окне записи, становится минусом проекта; его SHA-256 проверяется при импорте
в микс. Если файл изменился, рендер не заменяет его незаметно. Связь сохраняется
в индексе, если запись удалось индексировать; для старых, внешних или
неиндексированных дублей после перезапуска она может отсутствовать. Проверка
не является блокировкой файла и не защищает от целенаправленной одновременной
подмены; эффекты, ресемплинг и сведение в моно могут менять звучание.
Визард, физический микрофон и Windows 11 требуют проверки на целевом ПК.

При запуске `main.py`, установленной команды `zs-music-maker`, встроенных
аудиосмоуков и RVC-sidecar Numba использует отдельный временный JIT-кэш на
процесс. Это снижает риск обнаруженного повреждения общего кэша при параллельном
первом запуске, но не гарантирует отсутствия других нативных падений. Каждый
запуск может повторно компилировать функции и работать медленнее. Временный
каталог обычно удаляется при штатном выходе; после аварии или принудительного
завершения он может остаться в системном временном каталоге. Если задан
`NUMBA_CACHE_DIR`, это существующая родительская папка для новых отдельных
каталогов; старый кэш не удаляется. Проверка на Windows ещё нужна.

Для локальных тестов используйте `python -m tools.pytest_isolated tests/ -q`.
Прямой `python -m pytest`, сторонние программы и прямые импорты модулей не
изолируются автоматически. Если приложение встраивается как библиотека,
оберните весь запуск в `with isolated_numba_cache():` из
`app.core.numba_cache` **до импорта Numba**. Изоляция после импорта отклоняется;
внешние и дочерние процессы, не использующие эту защиту, остаются вне её
действия и могут унаследовать кэш родителя.

После перезапуска выберите «Проект → Открыть проект» и укажите папку с
`report.json`. Автоматического списка проектов нет. Для открытия требуется
сохранённый рецепт и контрольная сумма готового микса; старые отчёты без них
открыть нельзя. При пересборке мастера бит, текст и голос не меняются;
применяются текущие настройки стендов и экспорта стемов.

В новых полных прогонах также сохраняется манифест явно выбранных входных
файлов: референсов, минуса, вокала и путей к RVC-модели/индексу. Проверяются
все непустые указанные пути, даже если соответствующий режим сейчас выключен.
Если эти файлы успешно проверены до и после исходного прогона, после открытия можно
выбрать «Пересобрать всё»: программа повторно проверит их и скопирует в новый
проект. Неизменённый исходный проект при этом не перезаписывается. Если файл
отсутствует или изменился, полная пересборка блокируется, без подстановки.
Ранние проекты без манифеста поддерживают только пересборку мастера. Проверка
микса при открытии проекта пока синхронная и может задерживать интерфейс.

На экране открытого проекта с манифестом кнопка «Изменить и пересобрать»
позволяет явно выбрать изменения темы, артиста, дополнительных инструкций,
своего текста, текстового референса, заметок о трендах, BPM, числа куплетов,
сдвига вокала и экспорта стемов. Остальные настройки сохраняются из рецепта,
а невыбранные входные файлы проверяются и копируются. В этом же диалоге можно
явно заменить весь список референсов (или удалить их все), минус и вокальный
дубль. Новые файлы WAV/FLAC/OGG: до 10 минут, 8–192 кГц, моно/стерео, не более
4 ГиБ каждый, до 50 референсов. После подтверждения программа хеширует их в
фоновом потоке и показывает окно проверки с отменой. До завершения проверки
задача не ставится в очередь. Отмена прерывает проверку между чтениями; если
операционная система задерживает чтение сетевого файла, оно может завершиться
позже в фоновом потоке, который не запускает пересборку. Дальнейшая проверка и
копирование выполняются рабочим потоком. Заменённый старый файл может
отсутствовать; остальные исходники должны совпадать с манифестом.
Ни старые, ни выбранные файлы не перезаписываются.

Если у дубля есть сохранённая SHA-привязка к минусу, другой минус отклоняется,
даже после подтверждения. Для нового дубля проверяются известные метаданные
архива; если выбрана побайтовая копия старого дубля, сохраняется его прежняя
привязка. Для записи без привязки требуется явное подтверждение прав и того,
что пара не проверена; отчёт и окно результата показывают `UNVERIFIED`. Вручную
проверьте синхронизацию и права. Метаданные архива не доказывают, кто пел, и не
содержат хеш записанного вокала; физическая синхронизация не подтверждается.
Выбор нового дубля включает голос, если он был отключён; RVC и эффекты остаются
прежними. Модель RVC через этот диалог заменить нельзя.

Изменение текста **не перезаписывает и не перепевает** запись голоса; новый
текст может не соответствовать звучащей партии. BPM не растягивает импортированный
минус. При своих строках они имеют приоритет над генерацией; заметки не являются
автоматическим исследованием трендов. Полный визуальный редактор аудио и
восстановление полей мастера не реализованы. Варианты из открытого проекта,
другие частичные пересборки и прежний небезопасный `--resume` недоступны.

Новые отчёты содержат сохранённый рецепт, включая личный текст, заметки и
пути к локальным файлам. При полной пересборке в новом проекте также хранятся
копии входных файлов, включая голос и выбранные файлы моделей; требуется
дополнительное место на диске. Перед публикацией или передачей проверьте
содержимое и права. Если рецепт нельзя записать без потерь или входные файлы
не удалось проверить, отчёт сообщает об ограничении.

Пока идёт запись, рендер или есть задачи в очереди, штатное закрытие главного
окна блокируется: дождитесь завершения и закройте рекордер. Безопасной отмены
записи и задач пока нет; если движок зависнет, окно не закроется штатно.
Принудительное завершение программы или Windows может оборвать работу и оставить
неполные файлы, а отдельный AI-сервер может продолжить обработку.

Манифест не фиксирует программы, пресеты, встроенные сэмплы, версии или веса
внешних моделей, параметры сервисов и аппаратную среду. Результат полного
прогона может отличаться даже при совпадении входных файлов и seed. SHA-256
выявляет изменения, но не подтверждает авторство и не защищает от подделки
отчёта или злоумышленной одновременной подмены файлов.

**Важно для ранее созданных релизов:** старые версии генерировали похожий на
ISRC код без подтверждения присвоения и равномерно расставляли таймкоды строк,
не синхронизируя их с вокалом. Не используйте эти поля и LRC/SRT без проверки.
Теперь код не придумывается; введённый через API код помечается как
`USER_SUPPLIED_UNVERIFIED`, а текст сохраняется в TXT без фиктивных таймкодов.
ISRC необходимо получить у правообладателя или дистрибьютора.
Hit-score — эвристика, а не детектор ИИ и не гарантия успеха. Успешное создание
файла не означает, что он прошёл гейты качества; проверяйте отчёт проекта.
В отчёте новой полной версии `rebuild` указывает исходный ID, выбранные поля и
заменённые входы; `vocal_binding` описывает сохранённую, архивную или
неподтверждённую привязку. Для новых записей архив сохраняет SHA-256 вокального
файла и минуса; перед использованием проверяется вокал и создаётся отдельная
проверенная копия в проекте. Если файл записи изменён, вокал и микс блокируются.
Старые записи без исходного хеша вокала не становятся проверенными задним числом;
при новой паре требуется подтверждение, а в отчёте остаётся `UNVERIFIED`.
Повреждённый или противоречивый индекс блокирует выбор вместо скрытого обхода.
Копирование занимает дополнительное место; неиндексированные и старые записи без
хеша не имеют такой защиты. SHA-256 не подтверждает авторство, качество,
синхронизацию или подлинность отчёта и не защищает от злонамеренной гонки файлов.

`--ai-status` показывает текущую аппаратную диагностику, включая найденные
GPU и отдельно доступный PyTorch-бэкенд. Автовыбор Ollama работает только с
уже установленными поддерживаемыми моделями; проверки памяти приблизительны.
Не все движки и внешние серверы адаптируются автоматически. Отсутствующие
зависимости и упрощённые пути отражаются в статусах стадий. Опция
`install.py --ai` устанавливает только зависимости faster-whisper, без весов.
RVC может быть запущен в отдельном Python-окружении, чтобы не конфликтовать
с NumPy ядра; этот экспериментальный адаптер проверен только с фальшивым
backend, не с настоящей моделью или на Windows. См. `INSTALL.md`.

Референсный EQ использует все переданные аудиофайлы с равными весами по
мощности, сравнивая их на общей частоте дискретизации. Если пропускной полосы
референса недостаточно для всего микса, это отмечается отдельным проваленным
гейтом. Профиль приближённый: фильтры перекрываются, а zero-phase обработка
может давать предзвон на транзиентах. Проверяются несколько уровней коррекции;
если они ухудшают прежде пройденные гейты, сохраняется исходный микс и
показывается fallback. Повторные попытки увеличивают время и не заменяют
прослушивание. Для раздельной проверки конечного и исходного микса создаются
`mix_stage_report.json` и `mix_report.json`.

### Пересборка мастера: целостность и ограничения

Новый проект получает копию микса с проверкой размера и SHA-256 до и после
копирования. Статусы и гейты исходных этапов сохраняются с отметкой повторного
использования; исходный проект не изменяется. Контрольная сумма выявляет
повреждение/изменение файла, но не удостоверяет подлинность отчёта. В новом
проекте копируется только микс; остальные пути старых стадий — исторические
метаданные и не гарантируют самостоятельность для пересборки вокала или бита.
При открытии и перед копированием микс проверяется повторно; изменение отчёта
после открытия требует открыть его заново. Перемещение проекта поддерживается
на той же платформе при сохранении структуры папки. Проверка не защищает от
злоумышленной одновременной подмены и не подтверждает авторство или качество.
GUI, Windows и физическое аудиоустройство всё ещё требуют проверки.
